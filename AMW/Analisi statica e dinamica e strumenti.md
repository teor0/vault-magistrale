# Tipi di analisi e strumenti
Si distinguono 2 diverse tipologie di analisi: quella **statica** e quella **dinamica**.
L'analisi statica consiste nell'analisi con approccio white box, mentre l'analisi dinamica comprende sia l'approccio grey box che l'approccio black box. La peculiarità dell'analisi statica è che si studia il file binario senza mai eseguirlo. In pratica si lavora sul ”cadavere” del programma. A sua volta ne esistono due categorie: analisi statica di base e avanzata.
## Analisi statica di base
Come detto l'analisi statica di base è un approccio di tipo white-box. Consiste nell’esaminare il file senza guardare le istruzioni.
Un primo strumento è [VirusTotal](https://www.virustotal.com) che permette di analizzare file e firme digitali per confrontarli con quelli già analizzati per scovare malware. Attenzione non si calcola solo una firma digitale! La prima firma è quella fornita dal hash. Sotto Linux si possono usare `md5sum file`, `sha1sum file`, `sha256sum file` , `sha512sum file` per calcolare l'hash di un file. Attenzione pure a quale utilizzare dato che MD5 e SHA1 sono ormai stati deprecati visto che si possono "superare" come crittografie. In Linux, `hashdeep` è tool che offre molte funzionalità oltre al calcolo di vari tipi di hash. Dopo aver calcolato l'hash magari si vuole identificare il file in maniera dettagliata. Per farlo su Linux si può utilizzare `file`, che ritorna nel dettaglio il formato, l'architettura e se GUI o meno. Un'informazione importante è la frase (stripped to external PDB) che significa che nella compilazione sono state rimosse tutte le Informazioni utili per il debugging. Questa cosa è normale quando si produce un file .exe dato che solitamente appunto le informazioni di debug non sono utili al pubblico e vengono salvate su un file .PDB appunto. 
Si potrebbe analizzare il file con un antivirus, dove in Linux si può usare `clam` o meglio `clamscan file` per scannerizzare il file. Si possono poi cercare le stringhe all'interno del file! Tramite esse posso trovare le API che vengono chiamate il ché aiuta molto nell'analisi statica. In Linux si può utilizzare `strings file` che ritorna l'elenco delle stringhe con anche però i falsi positivi. Attenzione quando Windows utilizza la codifica UNICODE per le stringhe. Linux usa UNICODE-UTF-16 ovvero ogni stringa è fatta da 2 byte mentre i Windows c'è per ogni caso della confusione. In generale si utilizza UNICODE-UTF_16 little endian e tramite l'opzione `-e` di `strings` si può specificare la codifica. In Windows si può utilizzare il SysInternal `strings` che fa sostanzialmente la stessa cosa del tool Linux.
Si possono poi guardare le testate (header) del file. In Linux si può utilizzare `readelf file`, per file `elf` ma per file eseguibili Windows invece, debbo utilizzare tool specifici. Conviene dunque passare su Windows per utilizzare `CFF explorer`, `PEview`, `PEbear` e `pestudio`, quest'ultimo orientato all'analisi del malware. La prima testata è la testata DOS che è inutile per eseguire il file dato che è un retaggio di Microsoft, ma è utile per trovare le altre testate. La testata Nt contiene una sezione *File Header* che presenta le caratteristiche del file come architettura, numero delle sezioni, ecc. C'è poi la sezione *Optional Header* che contiene informazioni cruciali come AddressOfEntryPoint, ma attenzione non è l'indirizzo ma è in formato RVA (relative virtual address) ovvero l'offset da sommare all'indirizzo virtuale dove ho caricato il programma. C'è anche *Section Headers*. CFF explorer contiene anche un HEX editor per modificare i byte del programma, un disassembler lineare, dependency walker che consente di vedere le DLL che vengono utilizzati dal programma. Un tool utile è anche `dependency walker` che funziona meglio di quello di CFF explorer per elencare le DLL e la sua versione aggiornata `Dependencies`. Altro tool è `Resource hacker` che permette di modificare le risorse come icone, bitmap, stringhe ecc. memorizzate in una sezione apposita del file.

## Analisi statica avanzata
Per l'analisi statica avanzata iniziamo con il sysinternal `process explorer`, che mostra i processi attivi e le loro proprietà come il path, autostart location, meccanismi di sicurezza come DEP, ecc. Al suo interno c'è anche un bottone `Verify` che permette di verificare la firma dell'eseguibile. Inoltre permette di verificare le stringhe sia dell'eseguibile "morto" sia quando è in esecuzione in memoria e verificare se sono uguali o meno, visto che il malware tende a cambiare quando è in esecuzione.
C'è anche il sysinternal `process monitor` che guarda i processi in memoria e le loro interazioni con l'API di Windows.
Per vedere le chiavi di sistema esiste il tool `regedit` che contiene tutte le chiavi, si quelle di sistema sia quelle degli utenti. Ogni chiave di registro è un file che ha un percorso da una radice ad una foglia, dove la foglia è un valore associato chiave-valore con un tipo.
Il tool `Regshot` permette di salvare uno snapshot delle chiavi di sistema in modo semplice da confrontare con un secondo snapshot per visualizzare le differenze facilmente. Questo è molto utile dato che un processo può modificare ciascuna chiave di cui possiede il diritto d'accesso a tale file. Per quanto riguarda i tool per monitorare il traffico sulla rete, il più famoso è sicuramente `Wireshark`, ma esiste anche `ApateDNS` che permette di manipolare le risposte al DNS. Il tool `INetSim` permette in Linux di mettere in piedi un server simulato per comunicare con il malware in maniera sicura. C'è poi il tool `ApiMonitor` simile a process monitor ma che funziona più a fondo.
