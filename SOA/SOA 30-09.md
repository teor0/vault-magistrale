
Spectre-V1 sfrutta jmp condizionali per accedere dati del probe array. In particolare:
1. Si utilizza un if più volte con valori che soddisfano la condizione per addestrare il branch predictor a considerare tale if vero e quindi speculare.
2. Durante l’esecuzione speculativa, un indice `X` che dovrebbe essere rifiutato dal controllo viene usato per leggere `B[X]` oltre i limiti del array B, quindi alla seconda pagina di memoria. Il valore ottenuto seleziona una posizione in `A`, che lascerà nella cache un footprint.
3. Il valore letto viene combinato con uno spiazzamento, ad esempio uno shift di 12 byte ed è usato per accedere ad una posizione di A ed anche se la CPU scopre che la speculazione era errata ed annulla il risultato, il footprint resta visibile nella cache.
4. L’attaccante misura il tempo necessario per accedere alle varie posizioni di A e la posizione rimasta nella cache è più veloce da leggere e rivela il valore segreto che si vuole leggere.

Il codice utilizzato nel paper ufficiale di Spectre è il seguente: 
```
if (x <array1_size)
	y=array2[array1[x]*4096]
```
L'array B contiene anche parzialmente, una zona kernel. Tale zona è attaccata nella variante kernel dell'attacco. Da notare che l'array A è interamente user space, visto che l'attaccante deve poter misurare l'aggiornamento della cache. Ricorda, la patch software della kernel page isolation protegge dalla lettura diretta della pagina kernel. Nella variante kernel si passa un X che va a finire nelle pagine del kernel.
Per calcolare X uso `vaddr` che è l'indirizzo della zona kernel che voglio leggere speculativamente e l'indirizzo iniziale dell'array su cui accedo (Vedi codice per maggiori dettagli). Questo perché quando va effettuata una system call, il kernel va a scansionare una tabella in cui ogni entry è un function point, relativa alla system call da eseguire. Tale tabella ha N entry e se si passa un indice K>N si effettua un salto indiretto. Tale salto permette di caricare speculativamente una system call che utilizza la funzione detta *gadget* che usa i parametri nei registri scritti in precedenza dall'attaccante, quindi si sta utilizzando parametri user per eseguire codice tramite il kernel. Ricapitoliamo nel dettaglio l'attacco, ovvero Spectre-V2 che sfrutta i salti indiretti:
1. Si addestra il branch predictor per eseguire codice su un'indirizzo arbitrario, ovvero in un contesto di esecuzione A su una funzione A.
2. Nel contesto di esecuzione B, si preparano i parametri nei registri e si usa una funzione che condivide lo stesso indirizzo con la funzione A, così tramite speculazione si va a chiamare una system call con indice N+K.
3. In questo modo la system call utilizza una funzione gadget, che recupera i parametri dai registri per andare ad eseguire l'attacco.

![[spectre_v2.png]] Molto importante è che l'addestramento del branch predictor accada sullo stesso core della CPU, questo perché gli indirizzi devono coincidere tra A e B questo perché è possibile accedere alla cache per valutare la latenza mentre il leak di dati avvengono su altri core della CPU. La prima patch per evitare salti indiretti nel kernel è il <font color=orange>retpoline</font>, ovvero performare un salto indiretto utilizzando l'istruzione `ret` di x86. L'idea è la seguente:
- Salvare l'indirizzo target per il salto sullo stack
- Effettuo una chiamata ad pezzo di codice che rimuove l'indirizzo di ritorno del program counter dallo stack. Quindi si autoelimina.
- Questo pezzo di codice poi effettua il salto all'indirizzo target attraverso una istruzione di return
- La chiamata originale non ha quindi alcun return perciò le seguenti istruzioni sono un semplice loop infinito
- Il branch predictor per salti indiretti non potrà essere sfruttato per alterare il flusso di controllo speculativamente
  
  Vediamo il codice che implementa il retpoline:
```
	  push target_address
  1:   call retpoline_target
	  //put here whatever you would like
	  //typically a serializing instruction with no side effects
	  jump 1b
retpoline_target:
	lea 8(%rsp), %rsp //push dello stack pointer to target address
	//since FLAGS should not be modified
	ret //this will hit target_address
```
in questo codice l'unica istruzione speculativa è la return del retpoline. Il jump indietro permette di non avere attività di footprint in memoria.
